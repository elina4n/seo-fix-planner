# F02: Browser caching για JavaScript και CSS

Γράφτηκε: 10/11/2026, πριν από τη δοκιμή στον κλώνο.
Κατάσταση: hypothesis

## Η υπόθεση

Ο server στέλνει τα αρχεία JavaScript και CSS χωρίς οδηγίες για το πόσο καιρό
να τα κρατάει ο browser (Cache-Control). Αν μπουν αυτές οι οδηγίες, μέσω plugin
cache ή του .htaccess, φεύγει το πρόβλημα "Uncached JavaScript and CSS files".

## Η αλυσίδα

- **0.** Ο server δεν στέλνει header Cache-Control (ή Expires) για τα .js και .css.
- **1.** Το Semrush το καταγράφει ως "Uncached JavaScript and CSS files".
- **2.** Ένα plugin cache ή κανόνες στο .htaccess προσθέτουν το header, και το
  πρόβλημα φεύγει.

## Πηγές ανά κρίκο

- **0, 2. Το caching ρυθμίζεται με το Cache-Control.** Chrome for Developers,
  Lighthouse, "Serve static assets with an efficient cache policy":
  "HTTP caching can speed up your page load time on repeat visits." και
  "Configure your server to return the Cache-Control HTTP response header".
  https://developer.chrome.com/docs/lighthouse/performance/uses-long-cache-ttl
- **1.** Semrush Site Audit, "Uncached JavaScript and CSS files" (About the
  issue): "This issue is triggered if browser caching is not specified in the
  response header." Κατηγορία: Site Performance. How to fix: "If JavaScript and
  CSS files are hosted on your website, enable browser caching for them." και
  "If JavaScript and CSS files are hosted on a website that you don't own,
  contact the website owner and ask them to enable browser caching for them."
  και "If this issue doesn't affect your page load time, simply ignore it."
  (πρόσβαση 16/11/2026)
  Ο ορισμός ταιριάζει ακριβώς με τον κρίκο 0: το πρόβλημα εμφανίζεται όταν
  λείπει το header. Βεβαιότητα υψηλή.
- **Για το σχετικό πρόβλημα "Broken internal JavaScript and CSS files".**
  Semrush Site Audit (About the issue): "Any script that has stopped running on
  your website may jeopardize your rankings, since search engines will not be
  able to properly render and index your webpages." Κατηγορία: HTTP Status,
  Crawlability. How to fix: "Review all broken JavaScript and CSS files hosted
  on your website and fix any issues." (πρόσβαση 10/11/2026)
  Η κατηγορία "HTTP Status" δείχνει ότι τα αρχεία επιστρέφουν κωδικό σφάλματος,
  που στηρίζει την πιθανή σύνδεση με την F01. Το "How to fix" δεν λέει τι να
  κάνεις.

## Πιθανή εξάρτηση από την F01

Το Semrush βρίσκει και 16 "Broken internal JavaScript and CSS files". Αν κάποια
από τα ίδια αρχεία βγάζουν 404, τότε δεν έχει νόημα να μετρηθεί αν είναι
cached: πρώτα πρέπει να φορτώνουν. Αν ισχύει, η F02 εξαρτάται από την F01 και
το πραγματικό εύρος της φαίνεται μόνο μετά την F01.

## Εναλλακτικές εξηγήσεις

- Το caching υπάρχει, αλλά ο server το ακυρώνει για συγκεκριμένα αρχεία
  (π.χ. αρχεία από άλλο domain ή CDN). Ελέγχεται κοιτώντας τα headers ενός
  αρχείου στα Developer Tools του browser (Network).
- Κάποια από τα 17 αρχεία είναι σε domain που δεν ελέγχω (π.χ. Google Fonts,
  scripts τρίτων). Το ίδιο το Semrush λέει ότι αυτά τα διορθώνει μόνο ο
  ιδιοκτήτης τους. Τότε η F02 λύνει μόνο μέρος του προβλήματος και το resolves
  πρέπει να το λέει. TODO: στη λίστα των 17 αρχείων στο Semrush, πόσα είναι

## Παρατήρηση

Το Semrush γράφει "If this issue doesn't affect your page load time, simply
ignore it". Το ίδιο το εργαλείο δηλαδή λέει ότι η αξία της διόρθωσης εξαρτάται
από την επίδραση στην ταχύτητα, που μετριέται με το Lighthouse και όχι με το
audit. Υποψήφιο για χαμηλή θέση στη σειρά.

## Διάγνωση στο κανονικό site (16/11/2026)

- Το plugin cache είναι το WP-Optimize 4.5.3. Το page caching είναι ενεργό.
  Η καρτέλα "Static file headers" (εκεί όπου ρυθμίζεται το browser caching)
  εμφανίζεται κενή, και μετά από ανανέωση.
- Response headers του dashicons.min.css (συνδεδεμένη ως admin): Content-Encoding,
  Content-Type, Date, Last-Modified, Server: nginx, Vary. Δεν υπάρχει ούτε
  Cache-Control ούτε Expires. Επιβεβαιώνεται ο κρίκος 0 για αυτό το αρχείο.

## Ποιος server δίνει τα αρχεία

Τα στατικά αρχεία έχουν Server: nginx. Αν ο nginx τα δίνει μόνος του, χωρίς να
περνούν από τον Apache, τότε κανόνες cache στο .htaccess δεν θα τα επηρεάσουν.
Ίσως γι' αυτό η καρτέλα του WP-Optimize είναι κενή. Αν ισχύει, η διόρθωση
γίνεται στη ρύθμιση του nginx, δηλαδή από τον πάροχο του hosting ή από
εργαλείο του cPanel (TODO: υπάρχει κάτι με "NGINX" στο cPanel;), και η F02
έχει where: hosting αντί για caching_plugin. Θα φανεί στον κλώνο: προσθέτω
κανόνα cache και ελέγχω αν εμφανίζεται Cache-Control.
