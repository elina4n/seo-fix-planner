# F01: Να δουλεύουν ξανά οι εσωτερικές σελίδες (.htaccess / permalinks)

Γράφτηκε: 10/11/2026, πριν από τη δοκιμή στον κλώνο.
Κατάσταση: hypothesis

## Η υπόθεση

Μετά τη μεταφορά του site από το XAMPP στο cPanel, οι κανόνες του WordPress
για τα URLs (permalinks, στο .htaccess) δεν δουλεύουν. Γι' αυτό οι εσωτερικές
σελίδες βγάζουν 404 και από αυτό προκύπτουν τέσσερα από τα προβλήματα του
Semrush.

## Η αλυσίδα

- **0.** Οι κανόνες rewrite στο .htaccess λείπουν ή είναι λάθος (π.χ. έμειναν
  ρυθμισμένοι για υποφάκελο του XAMPP).
- **1.** Γι' αυτό οι εσωτερικές σελίδες βγάζουν 404 από τον Apache. Η αρχική
  ανοίγει, γιατί δεν χρειάζεται τους κανόνες.
- **2α.** Οι σελίδες με 404 εμφανίζονται ως "4xx errors".
- **2β.** Τα links προς αυτές εμφανίζονται ως "Broken internal links".
- **2γ.** Το sitemap δεν βρίσκεται, γιατί το WordPress το βγάζει μέσω των ίδιων
  κανόνων ("Sitemap.xml not found").
- **2δ.** Το hreflang δείχνει στο /en/home/, που βγάζει 404 και δεν δείχνει
  πίσω ("Issues with incorrect hreflang links").

## Πηγές ανά κρίκο

- **0–1. Τα URLs στηρίζονται σε κανόνες του .htaccess.** WordPress Developer
  Reference, WP_Rewrite::mod_rewrite_rules(): "Retrieves mod_rewrite-formatted
  rewrite rules to write to .htaccess."
  https://developer.wordpress.org/reference/classes/wp_rewrite/mod_rewrite_rules/
- **Διόρθωση.** save_mod_rewrite_rules(): "Updates the htaccess file with the
  current rules if it is writable."
  https://developer.wordpress.org/reference/functions/save_mod_rewrite_rules/
  Αν το αρχείο δεν είναι εγγράψιμο (Settings Permalinks Screen): "You need to
  manually copy everything in this text box into your .htaccess file to make
  your new Permalinks work."
  https://wordpress.org/support/article/settings-permalinks-screen/
- **2α. 4xx.** Semrush Site Audit, "4XX" (About the issue): "A 4xx error means
  that a webpage cannot be accessed." (πρόσβαση 10/11/2026)
- **2β. Broken internal links.** Semrush Site Audit, "Broken internal links":
  "Broken internal links lead users from one webpage to another and bring them
  to non-existent webpages." How to fix: "If a target webpage returns an error,
  remove the link leading to the error page or replace it with another
  resource." (πρόσβαση 10/11/2026)
- **2γ. Sitemap.** Make WordPress Core, "New XML Sitemaps Functionality in
  WordPress 5.5": το sitemap index είναι στο /wp-sitemap.xml και δουλεύει μέσω
  "rewrite rules used for the sitemaps".
  https://make.wordpress.org/core/2020/07/22/new-xml-sitemaps-functionality-in-wordpress-5-5/
  Βεβαιότητα μέτρια: το Semrush ψάχνει το /sitemap.xml και δεν ξέρω ακόμα
  ποιο sitemap βγάζει το site.
- **2δ. Hreflang.** Google Search Central, "Tell Google about localized
  versions of your page": "Each language version must list itself as well as
  all other language versions." και "If two pages don't both point to each
  other, the tags will be ignored."
  https://developers.google.com/search/docs/specialty/international/localized-versions
  Η πηγή δεν αναφέρει ρητά σελίδες με 404. Είναι δικό μου συμπέρασμα,
  βεβαιότητα μέτρια. TODO: "How to fix" του Semrush για το hreflang.

## Διάγνωση στο κανονικό site

Έλεγχοι που μόνο διαβάζουν, χωρίς αλλαγές στο site.

- Οι εσωτερικές σελίδες βγάζουν τη σελίδα "Not Found" του Apache και όχι τη
  σελίδα 404 του theme, άρα το αίτημα δεν φτάνει στο WordPress.

## Εναλλακτικές εξηγήσεις

- Ο crawler του Semrush μπλοκάρεται από τον server (το αναφέρει το ίδιο το
  Semrush). Αποκλείεται: οι σελίδες βγάζουν 404 και στον browser.
- Οι σελίδες σβήστηκαν ή είναι σε πρόχειρο. Ελέγχεται με το ?page_id=.
- Πρόβλημα μόνο στο plugin των γλωσσών. Ελέγχεται αν ανοίγουν οι ελληνικές.
- Ο server αγνοεί το .htaccess. Θα φανεί αν το Αποθήκευση στους Μόνιμους
  συνδέσμους δεν αλλάξει τίποτα.

## Παρατήρηση

Το "How to fix" του Semrush και για τα 4xx και για τα broken links είναι να
αφαιρεθούν ή να αλλάξουν τα links. Εδώ οι σελίδες υπάρχουν και το πρόβλημα
είναι στο .htaccess, οπότε αυτή η διόρθωση θα ήταν περιττή δουλειά που θα
έπρεπε να αναιρεθεί μετά την F01.
